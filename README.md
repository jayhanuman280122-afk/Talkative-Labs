# Clear Messages Checklist

A small, no-fuss checklist for writing messages people actually finish reading.
Works for chat, email, support replies, team updates, whatever.

I started this because I kept sending long messages that nobody answered, and
eventually figured out the problem was me, not them. Feel free to copy it,
change it, or ignore half of it.

## The checklist

Before you hit send, run through these:

- [ ] Is the answer or main point in the first line or two?
- [ ] Is there only one main idea? If not, can I number the parts?
- [ ] Did I say what happens next (or that nothing is needed)?
- [ ] Would I say this out loud to the person? Read it once and see.
- [ ] Any jargon the reader might not know? Swap it or explain it.
- [ ] Is there a warm-up sentence I can cut down?
- [ ] If I'm unsure about something, did I say so instead of guessing?

## A few examples

**Before**

> Hi! I hope you're well. I wanted to reach out regarding the thing we
> discussed earlier, and after looking into it a bit more there are a few
> different factors to consider...

**After**

> Short answer: yes, we can do it. Two things to check first, listed below.
> I'll confirm by tomorrow.

Not perfect, but the second one gets a reply faster. That's been true for me, anyway.

## For support and chat conversations

- Read the whole earlier thread before you reply.
- Don't ask people to repeat themselves after a handoff.
- "I'm not sure yet, let me check" beats a confident wrong answer.
- Keep a human tone even when part of the reply is automated.
